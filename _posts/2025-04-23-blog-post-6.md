## Overview

After training a PPO-based reaching policy for the UR5e in Isaac Lab, I performed a **Sim-to-Sim (Sim2Sim) transfer experiment** using a ROS2-based control pipeline.

Instead of running the policy directly inside the training environment, the policy was deployed through ROS2 and controlled a UR5e running in a separate virtual machine using the official UR ROS2 driver. Observations and actions were exchanged entirely through ROS2 topics, mimicking a real deployment scenario.

This setup serves as an intermediate validation step between pure simulation training and full sim-to-real deployment.

## Motivation

The objective was to verify that the trained policy:

- Is not tightly coupled to the Isaac Lab runtime
- Can operate through a realistic ROS2 control stack
- Remains stable when deployed through a driver interface
- Tolerates small runtime differences and communication latency

A successful Sim2Sim transfer increases confidence before executing sim-to-real experiments on physical hardware.

## Tools and Frameworks Used

- **Ubuntu 22.04**
- **ROS2 Humble**
- **skrl PPO implementation**
- **UR5e robot model**

## System Architecture

The system consisted of three main components:

### 1. Training Phase
- PPO policy trained in Isaac Lab
- Vectorized parallel environments
- Policy exported after convergence

### 2. Deployment Pipeline
- ROS2 used as middleware
- Standalone Python inference node
- Subscribes to joint states
- Computes observations
- Runs policy forward pass
- Publishes joint position commands

### 3. Target Simulation (Virtual Machine)
- Separate UR5e instance
- Controlled using `ur_robot_driver`
- Communication via ROS2 topics

All observations and actions were computed externally and transmitted through ROS2, ensuring clear separation between training and deployment.

## Launch Procedure

The UR driver was launched using:

```bash
ros2 launch ur_robot_driver ur_control.launch.py ur_type:=ur5e robot_ip:=192.168.56.101
```

Then the PPO interface node was launched:

```bash
python3 run_task.py
```

The implementation was based on and adapted from:

[Louislelay/Isaaclab_Sim2Real](https://github.com/louislelay/isaaclab_ur_reach_sim2real)

## Implementation Steps

1. **Observation Handling**
   - Subscribed to `/joint_states`
   - Constructed the policy observation tensor:
      - Joint positions
      - Joint velocities
      - Target position
   - Applied the same normalization used during training.

2. **Policy Inference:**
   - Loaded trained PPO checkpoint.
   - Disabled exploration noise for deterministic control.
   - Performed forward pass at control frequency.

3. **Action Publishing:**
   - Converted network output (tensor) into joint position commands.
   - Published commands to the UR driver controller.
   - Ensured joint ordering consistency.

4. **Control Loop:**
   - Closed-loop control entirely through ROS2.
   - Verified frequency stability and latency.
   - Matched training timestep scaling.

## Evaluation

The reach policy successfully controlled the UR5e in the separate VM-based simulation environment:
- No retraining required
- Stable convergence to target poisitions
- Acceptable latency through ROS2 communication
- No instability caused by driver-based execution

This confirms that the policy generalizes beyond the original Isaac Lab runtime and can operate through a realistic ROS2 control stack.
