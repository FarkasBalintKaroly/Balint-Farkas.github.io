## Overview

This project integrates the **SO-101 robotic arm** with **MoveIt2** and **NVIDIA Isaac Sim** using ROS 2 Humble. The goal was to create a simulation environment where motion planning can be performed through MoveIt in RViz while the resulting trajectories are executed by the robot model inside Isaac Sim.

Instead of using MoveIt2's standard mock hardware interface, the project connects the `ros2_control` layer directly to Isaac Sim through ROS2 topics. This creates a closed-loop setup in which MoveIt2 sends joint commands to the simulator and receives the simulated joint states in return.


## Tools and Frameworks Used

- **Ubuntu 22.04**
- **ROS2 Humble**
- **MoveIt2**
- **NVIDIA Isaac Sim**
- **RViz2**
- **SO-101 robotic arm**

## System Architecture

The integration connects MoveIt2 and Isaac Sim through the `topic_based_ros2_control` hardware interface.

The basic communication pipeline is:

```text
MoveIt2 / RViz
      │
      │ Planned joint trajectory
      ▼
ros2_control
      │
      │
topic_based_ros2_control
      │
      │ /isaac_joint_command
      ▼
NVIDIA Isaac Sim
      │
      │ /isaac_joint_states
      ▼
MoveIt2 / ros2_control
```

MoveIt2 is therefore responsible for motion planning, while Isaac Sim acts as the execution environment for the simulated SO-101 robot.


## Implementation Steps

### 1. SO-101 Robot Description

The workspace contains the robot description package for the SO-101, including the URDF and mesh files required by ROS 2 and MoveIt2.

The robot is divided into two MoveIt2 planning groups:

| Planning Group | Joints | DOF |
|---|---|---:|
| `arm` | Rotation, Pitch, Elbow, Wrist_Pitch, Wrist_Roll | 5 |
| `gripper` | Jaw | 1 |

The arm uses five controllable joints for positioning the end effector, while the gripper is handled separately through the jaw joint.

### 2. MoveIt2 Configuration

A dedicated MoveIt2 configuration package was created for the SO-101.

The arm is controlled using a `JointTrajectoryController`, while the gripper uses a `GripperActionController`.

Inverse kinematics is handled using the KDL kinematics plugin.

This allows target poses to be defined interactively through the MoveIt2 Motion Planning interface in RViz.

### 3. Isaac Sim Scene

A pre-configured Isaac Sim USD scene is included in the repository:

```text
so_101_arm.usd
```

This scene contains the SO-101 robot prepared for communication with ROS 2, avoiding the need to manually import and configure the robot model each time the simulation is started.

After opening the scene, the ROS 2 bridge is enabled and the simulation is started using **Play**.

### 4. ROS2 Communication

Communication between MoveIt and Isaac Sim is handled through two ROS2 topics:

| Direction | Topic |
|---|---|
| Isaac Sim → MoveIt2 | `/isaac_joint_states` |
| MoveIt2 → Isaac Sim | `/isaac_joint_command` |

The `/isaac_joint_states` topic provides the simulated joint state feedback to MoveIt2.

The `/isaac_joint_command` topic carries the joint commands generated by the MoveIt2 control pipeline to Isaac Sim.

This creates a closed-loop connection between motion planning and simulated execution.

### 5. Launching MoveIt2

After building and sourcing the ROS 2 workspace, the MoveIt2 environment can be started with:

```bash
source install/setup.bash
ros2 launch so_arm_moveit_config demo.launch.py
```

The launch file starts the required MoveIt2 components, including:

- `move_group`
- RViz with the MoveIt2 Motion Planning interface
- controller manager
- arm controller
- gripper controller
- joint state broadcaster

### 6. Motion Planning and Execution

Once Isaac Sim and MoveIt2 are running, a target pose can be defined for the SO-101 directly in RViz.

MoveIt2 calculates a valid trajectory from the current configuration to the requested target configuration.

After executing the trajectory:

1. MoveIt2 generates the joint trajectory.
2. `ros2_control` processes the trajectory.
3. `topic_based_ros2_control` publishes the joint commands.
4. Isaac Sim receives the commands and moves the simulated SO-101.
5. The resulting joint states are published back to ROS2.
6. MoveIt2 receives the updated robot state.

As a result, motion planning can be performed interactively in RViz while the actual simulated motion is executed and visualized in NVIDIA Isaac Sim.

## Outcome

The project resulted in a complete ROS2-based connection between **MoveIt2 and an SO-101 robot simulated in NVIDIA Isaac Sim**.

The final workflow can be summarized as:

```text
Target Pose in RViz
        ↓
MoveIt2 Motion Planning
        ↓
ros2_control
        ↓
ROS2 Joint Commands
        ↓
NVIDIA Isaac Sim
        ↓
SO-101 Motion
        ↓
ROS2 Joint State Feedback
```

This setup provides a practical environment for testing motion planning and robot control with the SO-101 while keeping MoveIt responsible for planning and Isaac Sim responsible for simulated execution.

The project also provides a useful foundation for further SO-101 experiments where more advanced control or learning-based methods can be integrated with the ROS2 and Isaac Sim environment.
